# Contributing to Kooka

Thanks for your interest in contributing to Kooka!

Kooka is a file manager written in Rust. Contributions are welcome, provided they follow the project's principles.

## Guidelines

- **Performance first.** Changes should minimise memory usage, CPU overhead and unnecessary dependencies.
- **Native by design.** Windows uses Win32; Linux will use GTK4.
- **Keep it simple.** Avoid unnecessary abstractions, dependencies and feature complexity.
- **Test your changes.** Ensure your code builds and behaves as expected before submitting a pull request.
- **Discuss major changes first.** Open an issue before implementing substantial features or architectural changes.

## AI Usage Policy — Level 1

Kooka is a human-written software project.

- **Allowed:** AI-assisted planning, research, documentation lookup and architectural discussions.
- **Prohibited:** AI-generated source code, including code produced by AI assistants or coding agents.

Contributors must write and understand their own code. Pull requests that violate this policy will be rejected. Repeated or deliberate violations may result in restrictions on future contributions.

## Contributor License Agreement

All code contributors must agree to the project's Contributor License Agreement (CLA) before their contributions can be merged.

The CLA allows Kooka to maintain flexibility in its future licensing and distribution.

CLA details and the signing process will be published before external code contributions are accepted.

## Pull Requests

1. Reference an existing issue or explain the purpose of your change.
2. Keep pull requests focused and reasonably small.
3. Describe what changed and how it was tested.
4. Include performance measurements where relevant.

## Reporting Issues

Use [GitHub Issues](https://github.com/ZFordDev/Kooka/issues) for bugs, feature requests and technical discussions.

For security vulnerabilities, follow [SECURITY.md](SECURITY.md) instead.
